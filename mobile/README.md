# Greenofig mobile wrapper

A Capacitor 6 Android wrapper that ships the live web app at
`https://greenofig.com` as a downloadable APK. Hybrid by design —
the APK is a chromeless WebView, so every web release reaches phones
on next launch without re-publishing.

## Layout

```
mobile/
├── capacitor.config.ts     app id, name, server.url
├── package.json            Capacitor + plugin deps
├── www/
│   └── index.html          tiny splash shown ~1s while WebView loads
├── scripts/
│   ├── sync-version.mjs    next/package.json → versionName/Code
│   └── inject-signing.mjs  patches release signing into build.gradle
└── README.md
```

The `android/` folder is **not committed**. It is generated by
`npx cap add android` on each build (locally and in CI). All custom
config lives in `capacitor.config.ts` + the two scripts above.

## Versioning

Single source of truth: `next/package.json`'s `version` field.

1. Bump it: `"version": "0.0.1"` → `"0.0.2"`.
2. Run `npm run sync:version` inside `mobile/` — emits
   `mobile/version.json` with the matching `versionName` + `versionCode`.
3. The CI workflow re-runs sync after `cap add android` to patch the
   generated `android/app/build.gradle`.

`versionCode` formula: `major * 1_000_000 + minor * 1_000 + patch`,
so `0.0.1 → 1`, `1.4.7 → 1_004_007`. Monotonic increases as long as
no semver part ever crosses 999.

## Building locally

```
cd mobile
npm install
npm run sync:version
npx cap add android        # generates the android/ folder
npx cap sync android
npm run sync:version       # patch the freshly-generated build.gradle
npm run build:apk:debug    # → android/app/build/outputs/apk/debug/
```

Open in Android Studio:
```
npm run open:android
```

## CI build (signed release APK)

GitHub Action: `.github/workflows/build-android.yml`.

**Trigger options:**
- Push a tag matching `v*` (e.g. `git tag v0.0.1 && git push --tags`)
  → Builds a signed release APK and attaches it to the GitHub Release
  with the same tag.
- Manual run via the Actions tab → "Build signed Android APK" →
  choose `debug` or `release`.

**Required GitHub Secrets** (Settings → Secrets and variables → Actions):

| Secret | What it is |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | The `.jks` keystore file, base64-encoded |
| `ANDROID_KEYSTORE_PASSWORD` | Password to open the keystore |
| `ANDROID_KEY_ALIAS` | Alias of the signing key inside the keystore |
| `ANDROID_KEY_PASSWORD` | Password for that specific key |

### Generating a signing keystore (one-time)

```
keytool -genkey -v \
  -keystore greenofig-release.jks \
  -alias greenofig \
  -keyalg RSA -keysize 2048 -validity 10000
```

Pick passwords, fill in the prompts (your name / org / country). Save
the file somewhere safe and back it up — losing it means future APKs
cannot upgrade existing installs.

Encode for the GitHub Secret:
```
base64 -w 0 greenofig-release.jks > keystore.b64
# Paste the contents of keystore.b64 into ANDROID_KEYSTORE_BASE64.
```

## Hosting the APK on Vercel

Two options:

1. **GitHub Release page (recommended)** — the CI action attaches
   the APK to the release for tag `v0.0.1` automatically. Link to it
   from the website:
   ```
   https://github.com/RawanGreenofig/greenofig/releases/latest/download/greenofig-<version>.apk
   ```
   The website itself doesn't use this URL — the GitHub Release
   page assets are version-tagged for traceability; the live link
   on greenofig.com is the stable `greenofig-latest.apk` that the
   CI publishes to `next/public/downloads/`.

2. **Drop into `next/public/downloads/` and serve from Vercel** — fine
   for small releases. APKs are large though (~5–10 MB), so this
   blows up the git repo over time. Prefer option 1.

Either way, on the web app you'll add a `<a href="..." download>Download
APK</a>` link. (Web-app side is intentionally untouched in Phase 1.)

## Local notifications (already wired)

`@capacitor/local-notifications` is in deps. From inside the web
app (once Phase 2 wires it up), the call pattern looks like:

```ts
import { Capacitor } from '@capacitor/core'
import { LocalNotifications } from '@capacitor/local-notifications'

if (Capacitor.isNativePlatform()) {
  await LocalNotifications.requestPermissions()
  await LocalNotifications.schedule({
    notifications: [
      {
        id: Date.now(),
        title: 'Lunch reminder',
        body: 'Time to log your meal.',
        schedule: { at: new Date(Date.now() + 60 * 60 * 1000) },
      },
    ],
  })
}
```

Outside Capacitor (web browser), `Capacitor.isNativePlatform()`
returns false and the call is skipped — no breaking change to the
web flow.

## FCM push (server side already wired)

The web app's existing `/api/push/subscribe` and `/api/notifications/send`
endpoints now handle both browser web-push and FCM tokens in parallel:

- POST `{ endpoint, keys: {...} }` → stored in `push_subscriptions`,
  dispatched via web-push (VAPID).
- POST `{ fcmToken, platform: 'android', appVersion: '0.0.1' }` →
  stored in `fcm_tokens`, dispatched via Firebase Admin.

For FCM dispatch to actually fire, add this env var in Vercel:

- `FCM_SERVICE_ACCOUNT_JSON` — the Firebase service-account JSON
  (Project settings → Service accounts → Generate new private key).

When the env var is missing, the FCM path no-ops cleanly — the
existing web-push pipeline keeps working.

Phase 1 wires the server side and the plugin dependency. Phase 2
will register the device token from the WebView (`PushNotifications.register()`)
and POST it to `/api/push/subscribe`.

## Adding the Firebase project (Android side)

1. Firebase Console → Add project → Android app with package name
   `com.greenofig.app`.
2. Download `google-services.json`.
3. Drop it at `mobile/android/app/google-services.json` after the
   first `cap add android` run. Commit it (it's not a secret — it
   identifies the project, doesn't authenticate).
4. CI doesn't currently copy it in — add the file to the repo or
   add a CI step to fetch it from Secrets if you prefer.
